## Problèmes rencontrés et résolus

| Problème | Cause | Solution |
|----------|-------|----------|
| `cargo` introuvable | Rust pas installé | Installé via rustup |
| `link.exe` échoue (GNU link) | VS Build Tools absent | Installé MSVC + SDK Windows |
| Moteur non chargé | Modèles au mauvais chemin (`WakaScribe\com.wakascribe.app\...`) | Copié dans `com.wakascribe.app\models\openvino\` directement sous `%LOCALAPPDATA%` |
| `Failed to read model: general error` | `openvino_ir_frontend.dll` manquante | Ajouté la DLL à côté de l'exe |

## Session du 09/02/2026 - Bugs transcription

### Problème constaté
Après un premier test concluant, un second essai (jour différent) produisait une transcription en **cyrillique** au lieu du français.

### Analyse
- La langue par défaut était `"auto"` → le modèle Parakeet TDT v3 (vocab 8193 tokens multilingue) choisit librement la langue
- En mode auto, aucune séquence de conditionnement n'est injectée dans le decoder LSTM
- Des variations subtiles d'audio (bruit, volume, position micro) suffisent à faire basculer le greedy decode vers des tokens cyrilliques
- Une fois le premier token cyrillique émis, l'état LSTM se conditionne et continue dans ce script

### Corrections apportées

| Fichier | Bug | Fix |
|---------|-----|-----|
| `src/lib/types.ts` | Default language `"auto"` | Changé en `"french"` |
| `src-tauri/src/engine/parakeet.rs` | `language: "en"` hardcodé dans le résultat de transcription | Remplacé par `language.code()` |
| `src-tauri/src/engine/parakeet.rs` | Pas de méthode pour obtenir le code ISO | Ajout de `TranscriptionLanguage::code()` (`"fr"`, `"en"`, `"auto"`) |
| `src-tauri/src/engine/mod.rs` | `language: "fr"` hardcodé dans `DynamicEngine::transcribe` | Remplacé par `language.code()` |

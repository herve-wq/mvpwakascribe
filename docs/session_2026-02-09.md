# Session du 9 février 2026

## Objectif

Bundler le sidecar CoreML (`parakeet-coreml`) dans le `.app` Tauri pour qu'il soit trouvé en production. Préparer un build testable sur machine arm64 (Apple Silicon).

## Travail effectué

### 1. Compilation sidecar arm64

- Compilé le sidecar Swift pour arm64 : `swift build -c release --arch arm64`
- Copié dans `src-tauri/binaries/parakeet-coreml-aarch64-apple-darwin`

### 2. Universal binary (lipo)

- Fusionné les deux binaires (x86_64 + arm64) en un seul universal binary via `lipo -create`
- Les deux fichiers suffixés (`-x86_64-apple-darwin` et `-aarch64-apple-darwin`) contiennent maintenant le même fat binary (~12 Mo chacun)
- Avantage : le `.app` fonctionne sur les deux architectures quelle que soit la machine de build

### 3. Configuration Tauri `externalBin`

- Ajouté `"externalBin": ["binaries/parakeet-coreml"]` dans `bundle` de `tauri.conf.json`
- Tauri sélectionne automatiquement le bon suffixe (`-{target_triple}`) au build et place le binaire dans `Contents/MacOS/parakeet-coreml`

### 4. Simplification `find_sidecar()` dans `coreml.rs`

- Supprimé les chemins dev hardcodés avec suffixe d'architecture
- Supprimé le bloc mort `#[cfg(feature = "tauri")]`
- Gardé : chemin bundlé (`exe_dir/parakeet-coreml`) + fallback dev (`binaries/parakeet-coreml`)

### 5. Correction log path dans `lib.rs`

- Les logs sont maintenant écrits dans `~/Library/Logs/wakascribe.log` au lieu du répertoire temp

### 6. Build de test avec modèles CoreML embarqués

- Build `npm run tauri:build` OK
- Copié manuellement les modèles CoreML (~461 Mo) dans `WakaScribe.app/Contents/Resources/model/coreml/`
- Modèles copiés : `Preprocessor.mlmodelc`, `Encoder.mlmodelc`, `Decoder.mlmodelc`, `RNNTJoint.mlmodelc`, `parakeet_v3_vocab.json`
- Le code `get_model_base_path()` trouve les modèles via `Contents/Resources/model/` (fallback #3 dans lib.rs)

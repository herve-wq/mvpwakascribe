## 1. Build initial — Mise en place de l'environnement

### Problèmes rencontrés et résolus

| Problème | Cause | Solution |
|---|---|---|
| `tauri: command not found` | `node_modules` absent | `pnpm install` (587 packages) |
| `is cmake not installed?` | `cmake` non installé (requis par `whisper-rs-sys`) | `brew install cmake` |
| `resource path ffmpeg-x86_64-apple-darwin doesn't exist` | Symlinks ffmpeg manquants pour x86_64 | Création manuelle des symlinks |
| `failed to bundle DMG` | Script `create-dmg` incompatible avec cette version macOS | Build avec `--bundles app` (skip DMG) |

### Commande finale de build

```bash
pnpm tauri build --bundles app
```

## 2. Bug critique — FFmpeg "Bad CPU type in executable"

### Symptome

Au lancement de l'app buildée, aucune transcription possible (ni enregistrement, ni fichier) :

```
Audio normalization (ffmpeg) failed: Failed to spawn
'/Applications/Voicetypr.app/Contents/MacOS/ffmpeg': Bad CPU type in executable (os error 86)
```

### Diagnostic

**4 causes racines identifiées** (voir `FFMPEG_X86_64_ARCHITECTURE_FIX.md`) :

1. **`ensure-ffmpeg-sidecar.cjs`** — Télécharge toujours les binaires ARM64 (`ffmpeg80arm.zip`), même sur Intel
2. **`ffmpeg/mod.rs`** — Candidats de résolution limités à `aarch64-apple-darwin`, pas de `x86_64`
3. **`build-parakeet-sidecar.sh`** — Force `swift build --arch arm64` même sur Intel
4. **`build.rs`** — Accepte les binaires sans vérifier l'architecture cible

### Corrections appliquées

#### Fichier 1 : `scripts/ensure-ffmpeg-sidecar.cjs`

- Détection de `process.arch` (`arm64` vs `x64`)
- Téléchargement conditionnel : `ffmpeg80arm.zip` (ARM) ou `ffmpeg80intel.zip` (Intel)
- Symlinks nommés avec le bon triple (`aarch64-apple-darwin` ou `x86_64-apple-darwin`)
- Checksums SHA256 : conservés pour ARM, skippés pour Intel (à pinner ultérieurement)

#### Fichier 2 : `src-tauri/src/ffmpeg/mod.rs`

- Ajout de `"ffmpeg-x86_64-apple-darwin"` et `"ffprobe-x86_64-apple-darwin"` aux listes `FFMPEG_CANDIDATES` et `FFPROBE_CANDIDATES`

#### Fichier 3 : `scripts/build-parakeet-sidecar.sh`

- Détection de `uname -m` pour déterminer l'architecture hôte
- Mapping vers le triple Rust (`arm64` → `aarch64-apple-darwin`, `x86_64` → `x86_64-apple-darwin`)
- Build Swift avec `--arch $SWIFT_ARCH` au lieu de `--arch arm64` en dur

#### Fichier 4 : `src-tauri/build.rs`

- Utilisation de `std::env::var("TARGET")` pour le triple cible
- Vérification de `ffmpeg-{target_triple}` en plus de `ffmpeg` générique
- Message d'erreur amélioré indiquant les deux chemins attendus

### Vérification post-build

```
ffmpeg:           Mach-O 64-bit executable x86_64 ✅
ffprobe:          Mach-O 64-bit executable x86_64 ✅
parakeet-sidecar: Mach-O 64-bit executable x86_64 ✅
voicetypr:        Mach-O 64-bit executable x86_64 ✅
```

## 3. Question Windows

**Constat** : le cross-compilation macOS → Windows n'est pas supporté par Tauri (WebView2, MSVC, NSIS, whisper-rs-sys natif). Il faut builder sur une machine Windows ou via CI GitHub Actions (`runs-on: windows-latest`).
